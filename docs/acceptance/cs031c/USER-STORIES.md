## Limits and semantics

Counts represent successful automatic submissions, not approvals, and are never refunded after rejection or original-worker cancellation. Eligibility failures consume nothing. Pausing/cancelling availability stops future submissions and retains pending requests already made. Same employee/shift is never automatically retried; a deliberate manual claim uses its existing independent checks. Existing confirmed CS-031B-2 rules become eligible when this increment runs; pause/cancel is available before further matching.

Matching requires the application server running. Relevant HTTP mutations are immediate, startup catches saved openings, and a 30-second interval reconciles remaining changes. Direct service integrations must use the matching adapter or explicit reconciliation; external edits/distributed deployment are not supported. The JSON-store locking contract is unchanged. Timer errors produce a generic storage-health message and retry at the next interval; startup storage failure prevents startup. No notifications/bell/email, no deployment and no design overhaul. Physical devices, other browser engines and multi-process distributed matching have not been certified here. CS-018 remains last.
